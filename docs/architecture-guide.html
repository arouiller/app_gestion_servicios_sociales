📊 Visión General

GestSocial es una aplicación web de gestión de servicios sociales. Permite a administradores y usuarios gestionar afiliados, grupos familiares y planes de servicio.

Stack Tecnológico

Backend Node.js + Express + Sequelize + MySQL

Frontend React + Axios + React Router + SCSS

Base de Datos MySQL 8.0 (Hostinger shared hosting)

Modelo de Arquitectura

Arquitectura cliente-servidor clásica con una capa de API REST en el medio:

Principios Arquitectónicos

🔀 Separación de Responsabilidades

Cada capa (Backend, Frontend) tiene roles bien definidos. Los servicios actúan como "puentes" entre el UI y la lógica.

🔐 Seguridad por Capas

JWT en el cliente, verificación en cada endpoint del servidor, roles de usuario (admin/usuario) controlados en middleware.

📦 Modularidad

Un modelo, controller, y route por dominio de negocio (afiliados, planes, etc.). Fácil de extender.

🔁 DRY (Don't Repeat Yourself)

Componentes genéricos reutilizables, servicios centralizados, middleware de validación común.

⚡ Performance

SPA (Single Page Application) en el frontend. Caché de datos en localStorage. Lazy loading en migraciones.

🚀 Escalabilidad

Transacciones BD para operaciones multi-tabla. Sistema de migraciones versionado. Deployment en Hostinger.

⚠️ Regla de Oro: Flujo de Datos Unidireccional

Componente → Service → API → Base de Datos

Nunca llamar axios directamente desde un componente. Siempre pasar por el service correspondiente. Esto mantiene la lógica centralizada y reutilizable.

📡 Flujo de Datos Completo

Vamos a seguir un ejemplo real: Crear un nuevo Afiliado

1. Frontend: Usuario interactúa

// Usuario hace click en "+ Nuevo" en GestionAfiliados.jsx
// Se abre un modal con un formulario

2. Componente React captura la entrada

// GestionAfiliados.jsx o GestionAfiliadosForm.jsx
const [formData, setFormData] = useState({ nombre: '', apellido: '', ... });

const handleSubmit = async (e) => {
  e.preventDefault();
  try {
    // ✅ Llamar al SERVICE, no directamente a axios
    const result = await afiliadosService.crear(formData);
    // ...
  } catch (err) {
    setError(err.message);
  }
};

3. Service prepara y envía al Backend

// frontend/src/services/afiliadosService.js
const afiliadosService = {
  crear: async (data) => {
    const { data: response } = await api.post('/afiliados', data);
    return response.data; // Retorna el nuevo afiliado creado
  }
};

// Nota: 'api' es la instancia Axios configurada con:
// - baseURL: '/api'
// - Interceptor que adjunta Authorization: Bearer <token>

4. Backend: Ruta recibe el request

// backend/src/routes/afiliados.js
router.post('/',
  verifyToken,                     // ← Middleware: Verificar JWT
  validate({...}),                 // ← Middleware: Validar entrada
  afiliadosController.crear        // ← Controlador: Lógica de negocio
);

5. Backend: Middleware de autenticación

// backend/src/middleware/auth.js :: verifyToken()
// Extrae el token del header Authorization: Bearer <token>
// Lo decodifica con JWT_SECRET
// Setea req.user, req.userId, req.userRole
// Si es inválido o expirado, retorna 401

6. Backend: Middleware de validación

// backend/src/middleware/validate.js
// Valida que los campos requeridos estén presentes
// Valida formatos (email, longitudes, etc)
// Si hay errores, retorna 422 con { errors: { campo: "msg" } }

7. Backend: Controlador procesa

// backend/src/controllers/afiliadosController.js
async crear(req, res) {
  const { nombre, apellido, ... } = req.body;

  // Crear instancia del modelo
  const nuevoAfiliado = await Afiliado.create({
    nombre,
    apellido,
    ...,
    fecha_creacion: new Date(),
    estado: 'activo'
  });

  // Responder al cliente
  res.status(201).json({
    success: true,
    message: 'Afiliado creado exitosamente',
    data: nuevoAfiliado
  });
}

8. Backend: Modelo interactúa con BD

// backend/src/models/Afiliado.js
const Afiliado = sequelize.define('Afiliado', {
  id: {
    type: DataTypes.INTEGER,
    primaryKey: true,
    autoIncrement: true
  },
  nombre: {
    type: DataTypes.STRING(100),
    allowNull: false
  },
  apellido: {
    type: DataTypes.STRING(100),
    allowNull: false
  },
  ...
}, { tableName: 'afiliados', timestamps: false });

// Sequelize traduce esto a SQL:
// INSERT INTO afiliados (nombre, apellido, ..., fecha_creacion)
// VALUES ('Juan', 'Pérez', ..., NOW());

9. Base de Datos: Inserción

MySQL query executed:
INSERT INTO afiliados
  (nombre, apellido, fecha_nacimiento, tipo_documento, numero_documento, ...)
VALUES
  ('Juan', 'Pérez', '1990-01-15', 'DNI', '12345678', ...)

10. Respuesta de vuelta al Frontend

// Backend retorna:
{
  "success": true,
  "message": "Afiliado creado exitosamente",
  "data": {
    "id": 42,
    "nombre": "Juan",
    "apellido": "Pérez",
    ...
  }
}

11. Frontend: Service procesa respuesta

// afiliadosService.crear() retorna el objeto del afiliado creado
// El componente recibe los datos en su .then() o async/await

12. Frontend: Componente actualiza UI

// GestionAfiliados.jsx
const result = await afiliadosService.crear(formData);
setAfiliados([...afiliados, result]); // Agregar a la lista
setShowForm(false);                    // Cerrar el modal
setSuccess('Afiliado creado!');       // Mostrar mensaje

✅ Flujo Completo Resumido

Usuario Click → Component State → Service (afiliadosService) → Axios Request → Backend Route → Middleware (Auth + Validate) → Controller → Model (Sequelize) → MySQL INSERT → Response JSON → Service Parses → Component Updates State → Re-render

🧩 Componentes Clave del Sistema

Backend: Autenticación (Auth Flow)

Archivos:

backend/src/middleware/auth.js — Verificación y generación de JWT

backend/src/models/Usuario.js — Modelo de usuario con hash de contraseña

backend/src/routes/auth.js — Endpoints de login y registro

Responsabilidades:

  • Login: Verificar credenciales, generar JWT, retornar token + datos usuario
  • Verificación: Decodificar JWT, extraer user info, pasar a req.user
  • Autorización: Verificar rol (admin vs usuario)

Backend: CRUDs Genéricos (Afiliados, Planes, etc.)

Patrón Repetido:

// Para cualquier entidad (Afiliados, Planes, GruposFamiliares):
frontend/src/services/[entidad]Service.js
backend/src/models/[Entidad].js
backend/src/controllers/[entidad]Controller.js
backend/src/routes/[entidad].js

// Operaciones CRUD:
CREATE (POST)   → controller.crear()    → Model.create()
READ (GET)      → controller.listar()   → Model.findAll()
UPDATE (PUT)    → controller.actualizar() → model.update()
DELETE (DELETE) → controller.eliminar() → model.destroy()

Transacciones para operaciones complejas:

Si una operación afecta múltiples tablas (ej: crear grupo familiar + agregar afiliados), usar transacciones:

const t = await sequelize.transaction();
try {
  await GrupoFamiliar.create({...}, { transaction: t });
  await Afiliado.update({...}, { transaction: t });
  await t.commit();
} catch (err) {
  await t.rollback();
  throw err;
}

  3. Backend ejecuta 2.0.1_*/upgrade.sql en transacción

🐛 Guía de Debugging y Troubleshooting

Encontrar y Arreglar un Bug

Escenario 1: El formulario no envía datos

Síntoma: Click en "Guardar" pero nada sucede, sin error visible.

  1. Verifica el navegador Console (F12)

    ¿Hay algún error en JavaScript? Busca un console.error() o Promise rejection.

  2. Verifica Network Tab

    ¿El request HTTP se está enviando? Busca GET/POST a /api/...

    ¿Qué estatus retorna? (200 = OK, 401 = no autenticado, 422 = validación, 500 = server error)

  3. Si hay error 422 (validación)

    El servidor rechaza los datos. Mira el JSON response: { errors: { campo: "msg" } }

    Busca la validación en: backend/src/routes/[entidad].js → función validate()

  4. Si hay error 401 (no autenticado)

    El JWT expiró o no se envía. Verifica:

    • frontend/src/services/api.js — ¿adjunta el Authorization header?
    • Browser DevTools → Storage → LocalStorage → ¿existe jwt_token?
  5. Si hay error 500 (servidor)

    Mira los logs del servidor (backend console):

    cd backend && npm run dev
# Deberías ver el error stacktrace en la consola

Escenario 2: Los datos no se guardan en la BD

Síntoma: El formulario retorna éxito (200), pero en la BD no aparecen los datos.

  1. Verifica el modelo Sequelize

    backend/src/models/[Entidad].js

    ¿El nombre de la tabla coincide con tableName: '...'?

  2. Verifica el controlador

    backend/src/controllers/[entidad]Controller.js

    ¿Está haciendo await Model.create(...)?

    ¿Los nombres de campos coinciden entre form → controller → modelo?

  3. Verifica si la tabla existe en la BD 
    mysql -u root app_gestion_servicios_sociales
mysql> SHOW TABLES;
mysql> DESC [tabla];  # Ver estructura

    Si la tabla no existe, necesitas ejecutar la migración:

    cd backend && npm run db:migrate:up
  4. Habilita logging SQL

    backend/src/config/database.js

    Agrega logging: console.log a Sequelize para ver los queries SQL.

Escenario 3: CORS error (solicitud bloqueada)

Síntoma: Error en console: "Access to XMLHttpRequest... has been blocked by CORS policy"

  1. Verifica que el backend tenga CORS habilitado

    backend/src/index.js

    const cors = require('cors');
app.use(cors({
  origin: process.env.FRONTEND_URL || 'http://localhost:3000',
  credentials: true
}));
  2. En desarrollo, verifica que el proxy esté configurado

    frontend/package.json

    "proxy": "http://localhost:5000"

    O en el service Axios:

    axios.create({
  baseURL: process.env.REACT_APP_API_URL || 'http://localhost:5000/api'
});

Casos Comunes

¿Button no responde?

Verifica:
• ¿El onClick está bien escrito?
• ¿Hay un console.error()?
• ¿El button está dentro de un <form> con preventDefault()?

¿Modal no abre?

Verifica:
• ¿El estado showForm es true?
• ¿El z-index es suficiente (>= 1000)?
• ¿CSS visibility/display no bloquean?

¿API retorna error 404?

Verifica:
• ¿La ruta existe en routes/?
• ¿El endpoint está registrado en index.js?
• ¿El path es exacto (sin /api double)?

¿Datos no actualizan en lista?

Verifica:
• ¿Hiciste await loadRegistros() después de guardar?
• ¿El state cambió (no solo los datos)?
• ¿El componente re-renderea?

🎓 Resumen: Cómo trabajar con GestSocial

Para encontrar un bug:

  1. Abre Browser DevTools (F12) → Console para ver errores JavaScript
  2. Mira Network tab → ¿El request HTTP llegó? ¿Qué status?
  3. Si es error 422: revisar validación en backend/src/routes/
  4. Si es error 500: revisar logs con npm run dev en backend
  5. Si no hay request: revisar el componente React y el service
  6. Mira la BD: ¿Existen las tablas? ¿Hay datos?

Para agregar una funcionalidad similar a las existentes:

  1. Copia el patrón (ej: si es un CRUD, usa el patrón Afiliados)
  2. Backend: modelo → controller → route → migración
  3. Frontend: servicio → componente wrapper → agregar a menú
  4. Usa LookupCRUD si es un listado simple con C/R/U/D
  5. Haz un request POST/GET/PUT/DELETE y verifica logs

Principios a recordar:

  • 🔀 Flujo de datos: Componente → Service → API → BD
  • 🔐 Autenticación con JWT: Bearer token en Authorization header
  • ✅ Validación en dos lugares: Frontend (UX) + Backend (seguridad)
  • 📦 Un modelo, controller, route por dominio
  • 🎯 Componentes reutilizables genéricos (LookupCRUD, etc.)
  • 💾 Migraciones versionadas para cambios de BD
