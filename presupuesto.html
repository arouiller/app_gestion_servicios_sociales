Glosario de siglas y términos técnicos

Las siglas que aparecen en este documento corresponden a estándares internacionales de estimación de software y a terminología habitual del desarrollo web. Se listan a continuación para facilitar la lectura.

PF: Punto de Función
Unidad de medida del tamaño funcional de un sistema de software. Cuantifica cuánto "hace" el sistema desde el punto de vista del usuario, independientemente de la tecnología utilizada.
IFPUG: International Function Point Users Group
Organismo internacional que define y mantiene el estándar de conteo de Puntos de Función. La metodología se usa mundialmente para estimar esfuerzo de desarrollo.
ILF: Internal Logical File (Archivo Lógico Interno)
En la metodología IFPUG, representa un conjunto de datos que el propio sistema crea y gestiona; en la práctica equivale a una tabla en la base de datos del proyecto.
EI: External Input (Entrada Externa)
Operación que recibe datos del usuario y los guarda o procesa: crear un registro, editarlo o eliminarlo. Cada formulario de alta o modificación es típicamente un EI.
EO: External Output (Salida Externa)
Pantalla o reporte que muestra información procesada o calculada, como un listado con totales, un recibo generado o una vista de impresión.
EQ: External Inquiry (Consulta Externa)
Operación de búsqueda o lectura de datos sin modificarlos, como un buscador de afiliados o la visualización del detalle de un plan.
API: Application Programming Interface
Conjunto de servicios que el servidor pone a disposición de la aplicación web. El frontend "habla" con el servidor exclusivamente a través de la API, usando los métodos HTTP (GET, POST, etc.).
CRUD: Create, Read, Update, Delete
Las cuatro operaciones básicas sobre cualquier conjunto de datos: Crear, Leer, Actualizar y Eliminar. Toda entidad del sistema (cobradores, planes, etc.) tiene su propio CRUD.
SQL: Structured Query Language
Lenguaje estándar para crear y consultar bases de datos relacionales (MySQL, PostgreSQL, etc.). Las migraciones del proyecto se escriben en SQL.
PK: Primary Key (Clave Primaria)
Campo que identifica de forma única cada registro en una tabla. Por ejemplo, el número de afiliado es la clave primaria de un plan.
FK: Foreign Key (Clave Foránea)
Campo en una tabla que referencia la clave primaria de otra tabla, estableciendo una relación entre ambas. Garantiza integridad: no se puede asociar un cobrador inexistente a un plan.
JWT: JSON Web Token
Token de seguridad cifrado que el servidor entrega al usuario al iniciar sesión. El navegador lo envía en cada petición para demostrar que el usuario está autenticado, sin necesidad de guardar contraseñas en el servidor.
HTTP: HyperText Transfer Protocol
Protocolo de comunicación entre el navegador y el servidor. Define métodos como GET (leer), POST (crear), PUT (reemplazar), PATCH (modificar parcialmente) y DELETE (eliminar).
CSS / SCSS: Cascading Style Sheets / Sassy CSS
CSS es el lenguaje que define el aspecto visual de las páginas web (colores, fuentes, espaciados). SCSS es una extensión de CSS que facilita su escritura mediante variables y anidamiento.
UI: User Interface (Interfaz de Usuario)
Todo lo que el usuario ve e interactúa en pantalla: botones, formularios, tablas, menús. El desarrollo de UI abarca tanto la lógica de interacción como los estilos visuales.
ENUM: Enumeration (Enumeración)
Tipo de campo cuyo valor solo puede ser uno de una lista cerrada de opciones predefinidas. Por ejemplo, el estado de un plan solo puede ser ACTIVO o SUSPENDIDO.
PDF: Portable Document Format
Formato de documento digital desarrollado por Adobe, ampliamente utilizado para impresión. Los recibos del sistema se generan en este formato para garantizar una presentación uniforme en cualquier dispositivo.
Requerimientos funcionales cubiertos

El presente presupuesto cubre el desarrollo de las siguientes funcionalidades, descriptas en términos del negocio.

# Requerimiento Descripción
1 Gestión de Cobradores Registrar, modificar y eliminar los cobradores que pueden ser asignados a los planes. El sistema impide eliminar un cobrador que tenga planes asociados.
2 Gestión de Tipos de Plan Registrar, modificar y eliminar los tipos de plan disponibles en el sistema (ej. plan básico, plan familiar). El sistema impide eliminar un tipo en uso.
3 Gestión de Obras Sociales Registrar, modificar y eliminar las obras sociales que pueden vincularse a los planes. El sistema impide eliminar una obra social que ya esté asignada.
4 Gestión de Servicios Adicionales Registrar, modificar y eliminar los servicios opcionales que los integrantes de un plan pueden contratar. El sistema impide eliminar un servicio que esté en uso.
5 Gestión de Tipos de Grupo Registrar, modificar y eliminar los tipos de grupo disponibles (ej. Individual, Grupo familiar, Titular y adherente).
6 Gestión de Planes Registrar, editar y eliminar planes con todos sus datos: número de afiliado, cobrador, obra social, tipo de plan, tipo de grupo, domicilio, localidad, teléfonos, valor de cuota y estado (activo / suspendido).
7 Numeración automática de afiliado Al crear un plan nuevo, el sistema puede sugerir automáticamente el próximo número de afiliado disponible, evitando errores de duplicación.
8 Gestión de Integrantes de un Plan Agregar, editar y eliminar los integrantes de cada plan, con sus datos personales (apellido, nombre, documento, fecha de nacimiento, fecha de cobertura), su rol dentro del plan (titular o integrante) y los servicios adicionales que contrata.
9 Reutilización de personas existentes Al agregar un integrante a un plan, el usuario puede buscar si esa persona ya está registrada en el sistema (por nombre o documento) y vincularla sin volver a cargar sus datos. Si no existe, se puede crear en el mismo paso.
10 Historial de cambios de cuota Consultar, por plan, el registro completo de todas las modificaciones que tuvo el valor de la cuota a lo largo del tiempo, con fecha y valores anterior y nuevo.
11 Aumentos masivos de cuota Aplicar un porcentaje de aumento a uno, varios o todos los planes al mismo tiempo. Antes de confirmar, el sistema muestra una previsualización con el valor actual y el nuevo valor de cada plan afectado.
12 Generación de recibos Generar recibos para un período determinado (mes y año) para todos los planes activos o solo para los seleccionados. Si un recibo ya fue generado para ese período y plan, el sistema lo omite sin error.
13 Impresión de recibos Imprimir los recibos generados en un formato estructurado y listo para entregar al afiliado, con los datos del plan, el titular, todos los integrantes y el monto de la cuota. Cada recibo ocupa una página individual.
14 Búsqueda de Afiliados Buscar afiliados por nombre, apellido o número de documento. Al seleccionar uno, se consultan todos los planes en los que participa y se puede acceder al detalle completo de cada uno.
15 Listado general de Planes Consultar y filtrar todos los planes del sistema por estado, cobrador, obra social o número de afiliado. Permite acceder al formulario completo de cualquier plan desde el listado.
16 Listado de Planes por Cobrador Seleccionar un cobrador y ver todos los planes que tiene asignados, con sus datos principales. Permite acceder al formulario completo de cada plan.
17 Interfaz adaptada a dispositivos móviles La aplicación es completamente utilizable desde teléfonos y tabletas, con una navegación simplificada y formularios adaptados a pantallas pequeñas.
18 Mensajes de error comprensibles Ante cualquier error (validación, registro duplicado, elemento en uso, falla de conexión), el sistema muestra un mensaje claro en lenguaje llano, con la opción de ver el detalle técnico para quien lo necesite.
